# v18 · 从审阅到定版

## 交付与边界

- 196 秒、1080p60，原生 3840×2160 渲染后 Lanczos 降采样，H.264 CRF 18；无音轨画面版与声音版分开保存。
- 保留 v16/v17 的叙事、镜头、页面、材质、自然微晃与章节色温；本轮只做“让论证被看见、被读完”的修正，不新增产品能力或机制。
- 不加入实机录像、不声称未经验证的完成、成功率或自动泛化。片尾“真机实验 R1–R3 · 20 位老人试用记录，见佐证材料”是材料索引，不是结果声明。
- 旧版本全部保留，不覆盖 v17 画面版与 v17 声音 v01–v04b。

## 关键取舍

- **删掉三张大值标题**，而不是继续调整它们的位置。三张卡内的值已经可读；大值在透视叠放时必然压住下一张卡。少一层，观众多看见一层。
- **结尾不回手机**。手机在 174–179 已经完成“下一次只装入匹配方法”的动作；结尾再回来只会与总结抢中心。总结退场、空镜、品牌落定，比“手机穿过总结”更稳。
- **暂停用全幅卡**。这不是新机制，只是把 v17 已有的“已暂停，等您决定”从右下小卡提升为一次真正的停顿；系统退到 5%，话留在画面中央。
- **不添加实机镜头**。没有可用素材时不伪造；片尾用索引指向佐证材料，保持“机制演示”的诚实边界。

## 验证

- 1x 全片预览 11760 帧，逐段 0.5 秒采样检查结尾、读表、提交、来源、影子、暂停与开头。
- 35–40 秒暂停字块在最终源上补渲 300 帧（4K）后重新编码；其余 11460 帧为一次连续 4K 渲染。补渲只改暂停字块位置与退场，不涉及其它镜头。
- 4K 原生渲染前跑 `fusion-finish-check` 与 `fusion-scenery-check`；全片 11760 帧连续、无空帧、分辨率与确定性检查。
- 编码后 `validate.py` 检查时长、帧数、完整解码、峰值与黑帧；`fusion-audit.py` 在提供预检目录时对照原生帧。
- 声音版另跑 `soundtrack_v18.py`：复用 v03 钢琴预混，按 v18 冻结源重新导出 75 个落点与 26 段连续动作，逐帧对齐后再混音、母带、封装。

## 复现

```bash
cd video
node render/fusion.mjs 2
# 声音（画面完成后）
OPENBLAS_NUM_THREADS=2 tmp/audio-venv/bin/python render/soundtrack_v18.py --output out/review/fusion-v18-sound
```

`fusion.mjs` 会拒绝覆盖已存在的 `out/review/fusion-v18`；重跑前先确认旧目录已按需归档。声音脚本同样拒绝覆盖已完成的 `fusion-v18-sound`。
