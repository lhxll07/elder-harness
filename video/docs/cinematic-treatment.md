# 电影化机制镜头 · 六镜实施版

依据本轮反馈，将六个机制镜头改写为具体对象上的连续变化。保留已经认可的第一镜、旧片和未完成帧。
六镜已接入 214 秒时间轴；完整渲染、编码和验收以对应版本目录里的 film.json、validation.json 为准。

正文文案与叙事层级以 `narrative.md` 为准：架构总览 → 一次办事 → 方法与经验。字幕、画内短标和章节导航同步组织；下文中的技术边界作为制作依据，避免逐镜重复播报。

## 后半段质感精修

后续整片质感升级以 `supersampling.md` 为准：保留镜头和文字，统一柔光影棚、精密手机与完整指触模型，并以 4K 原生渲染下采样输出。颗粒、色散和抗锯齿改为整片统一的克制设置。

保持 214 秒章节、字幕和复诊故事不变，精修范围从家人端（104 秒）延伸到片尾。

- 后半段逐渐降低色散、颗粒与暗角，加入渐入的 FXAA；字幕仍在后处理之后绘制，不被抗锯齿或景深模糊。
- 家人电脑改为圆润金属外壳，补齐键盘、触控板、转轴和摄像头；真实网页内容继续采用虚构示例数据。
- 留言具有纸纤维、纸厚与折痕阴影，回执改成有厚度的精细标签；不改变提交、送达、本人已读、本人确认继续的边界。
- 折带、证据页、方法页和表格具有层压边缘；阅读尺采用透明薄膜与金属转轴，文字和当前列始终优先可读。
- T0/T1/T2 改为同一实体试验台的三个工位，先总览，再看双轨回放与关闭的实机门；版本采用有层次的经验盒，active 仍指向旧版，候选不自动上线。
- 片尾采用正中品牌、精细麦克风徽记、双层细轨和稳定留白；不添加未经验证的业务成功或性能成绩。
- 全部变化由绝对时间决定，保留章节边界相同的手机姿态与镜头参数；旧片与中断产物不覆盖。
- 复核整片后上移试验台工位标题，避开印章；缩短阅读尺末端，给排班表标题与说明留下间距。

## 第一镜为什么成立

真正的办事页面形成可感知的纵深；镜头转向侧面，让繁琐步骤获得体积；页面折叠回手机，压缩动作直接解释降低理解成本。
它不是“一个隐喻 + 一段说明文字”，而是问题、变化、结果在同一个物体上发生。

新镜头采用同一原则：先让观众遇到具体障碍，再看系统如何处理。每个镜头只保留一个主动作。
技术事实写进空间、对象身份、行动边界和结果，而不是堆叠名词。关字幕后仍应能看懂主要因果。
镜头运动跟随目标、信息或选择权的转移，不用无目的环绕制造“高级感”。

## 01 · 同一页，揭开两层世界

**机制：双通道互补。建议 12—15 秒。**

- 起：医院页面占满画面。一个图形入口清楚可见，但结构化控件通道没有给出可用标记。观众先看到“看得到，却缺少可操作线索”的矛盾。
- 展开：屏幕沿厚度分离为两层。前层保留真实像素，后层是文字、控件身份和关系；文字控件的位置仍和原页一一对应。后层在图形入口处留有缺口，不凭空补造控件。
- 运镜：从正面快速贴近缺口，沿页缘横移到侧面；像素层的图形轮廓与结构层的已有线索在同一位置汇合。不是两条彩色管线传递抽象卡片。
- 收：两层重新贴回当前页面，留下一个可解释的目标标记；线索不足时仍停下，不暗示识别必然成功。
- 只留一句：“不是多看一遍，而是补上另一种看法。”
- 技术短标：结构信息 / 像素信息 / 当前页绑定。视觉需本人授权且非敏感页；不是双模型投票，也不是两份脚本。

## 02 · 页面换位，旧动作扑空

**机制：ScreenActionGuard。建议 14—17 秒。优先制作。**

- 起：医院入口“普通内科”已被观察到，一条指向它的动作轨迹正在形成。页面重排，目标滑到另一处，原位置出现其他入口。
- 冲突：镜头跟随旧轨迹前冲，几乎撞向错误位置。动作在真正触屏之前被截住。观众应先产生“等等，那里已经不是刚才的按钮”的直觉。
- 解法：镜头借减速转向侧面。同一个控件的文字、resourceId、父子和兄弟关系形成连续身份线，随它移动而不是固守原坐标。旧、新页面唯一匹配后，工具调用重绑定到当前目标。
- 反例：两份完整稳定身份同时出现，轨迹分叉但两路都不触屏；回到重新观察。若需压时长，把此分支放入下一小节，不塞进主动作高潮。
- 收：正常分支在当前页执行，进入医生列表，继续同一次复诊。
- 只留一句：“页面可以换位，动作不能凭记忆。”
- 技术短标：app / windowId / 尺寸一致；enabled + 直接可操作；旧、新页身份均唯一。坐标工具跨 revision 直接拒绝，不把身份重绑定包装成追踪任意移动按钮。

## 03 · 信息过来了，控制权没有过去

**机制：家人协作与本人恢复。建议 18—22 秒。**

- 起：医生选择前，当前办事路径缺一段。老人说“不记得了，问问女儿”，任务停下。
- 展开：镜头从老人手机掠过空缺，来到另一侧的真实家人网页。求助背景在页面上展开，家人在真实留言区域写下“上次陈医生，您再核对一下”。
- 主动作：留言从网页折成一张纸，镜头跟纸穿过空间回到老人手机。它经历提交、到手机、本人已读三个回执；同一张纸获得状态，不再排列三个重复说明框。
- 关键转折：纸到手机后展开为大字留言，但任务路径仍断着。补充信息不等于执行授权。只有本人核对并说“是陈医生，周四上午，继续”，路径才接上。
- 收：回到同一医生与时间选择，不重开一个孤立的家人端功能介绍。
- 只留一句：“家人补上信息，您接回决定。”
- 边界：不是远程控制；留言不进入 Agent 任务指令；接手不等于办成。真实网页配示例数据，端到端实机协作未验证，通知适配器当前只记日志。

## 04 · 页面都折回去了，最后一按留下来

**机制：分级自主与本人关键操作。建议 12—16 秒。**

- 起：已明确的预约步骤沿一条真实页面构成的折带展开。医院、科室、医生、日期依次可见；不把尚未知的信息猜成已知。
- 展开：镜头沿折带低位前行，普通步骤随着任务推进折回手机。折带越来越短，观众直接看到“系统接过了步骤”。
- 转折：到了“提交预约”，折叠突然停止。其他页面都收好，关键按钮和待核对信息仍留在本人面前。不是所有动作一股脑压成自动完成。
- 运镜：从快速随行切为稳定正面，给本人判断的时间。本人指尖从与系统轨迹不同的一侧进入并点按。
- 收：页面返回等待状态；本人明确要求继续核对后才进入结果检查。
- 只留一句：“压缩的是步骤，不是您的决定。”
- 技术短标：可逆且已明确 → 普通代办；信息缺口 → ask_user；对外承诺 / 不可逆 / 敏感验证 → ask_person 或交还本人。

## 05 · “成功”两个字，站得住吗？

**机制：完成声明、独立证据与本机先行。建议 16—20 秒。**

- 起：明确标为反例，一句“预约成功”沿着办事记录形成。医院当前页面却写着“待医院确认”。先让观众看见这两个状态的冲突。
- 展开：镜头潜到这句声明下面，页面证据从本轮记录中展开，逐个支撑有来源的事实。每份证据带 app、revision、step，不让过去任意看到的内容作证。
- 转折：“成功”下面没有对应业务回执，无法获得支撑，脱离整句落下；正文改为“已提交，待医院确认”。这是证据约束，不是模型信心评分。
- 技术插入：同一段自己输入、再从输入框读回的文字形成闭环，却不能接入独立证据支撑层。动作记录只配对 tool_call_id 与工具返回，不把本人手指动作伪造成日志。
- 收：本机核验拒绝时，声明不能进入模型复核通道；只在机械检查与完成审计通过后进入 CloudReviewer。镜头随有效记录回到手机的精确状态。
- 只留一句：“说得像完成，不等于真的办成。”
- 边界：所有对比为机制示意。COMPLETED 不是外部业务成功；SELF_TYPED 和敏感页不能作独立事实，数值还需匹配字段与单位。

## 06 · 一页方法，展开成一把读表的尺

**机制：Push–Pull、load_skill 与 reading_tables。建议 14—18 秒。**

- 起：示例排班表铺满画面。相邻列很像，读取线索偏到邻列；日期和医生被错拼的危险是看得见的，而不是先讲“技巧库”。
- 拉取：常驻的是小目录；镜头从目录边缘抽出 reading_tables 的一页方法，其他方法不展开。可短暂看见真实工具名，不展示虚构 token 节省率。
- 主动作：这页方法沿折痕打开，变成对齐表头的阅读尺。先锁定“周四”，再沿该列逐条读取，每条都带上列头；日期 / 时段 / 医生作为一组进入对话记录。
- 反例：读到另一列的表头，阅读尺亮起冲突提示，返回表头重新数列，不悄悄把邻列算进答案。
- 收：阅读尺折回方法页，表格回到手机。方法帮助模型找读法，不是保存一条固定坐标脚本。
- 只留一句：“拿来的是方法，不是上一次的坐标。”
- 技术边界：阅读尺是内置技巧指导模型的可视化，不是声称已实现刚性表格识别算法；load_skill 正文进入 transcript，当前页面守卫与人工操作边界仍有效。

## 选镜与节奏

本轮六镜全部实施，分别接入 observe、loop、guard、handback、evidence、teach；保持 214 秒总长与前两镜。
它们仍挂在同一次复诊故事上，不额外叠加一组科幻片头。
每镜的兴趣曲线是：具体障碍 → 一个可感知的变化 → 清楚的结果；阅读技术短标的时间留在动作减速段。
重复元素服务于前后呼应：第一镜收起繁琐，第四镜只留下本人决定。不要每镜都做同一种折叠，也不要换一组无关隐喻。

制作时保留现有实现的限制：完整渲染当前分镜后编码，不打开审片页，不混接新旧源码对应的帧，旧版本不覆盖。

## 构图与连续性修订

- 剥层主体展开时手机完全退场，像素层与结构层同时分离位置和深度，避免手机挡住结构缺口。
- 淡入淡出的透明几何不写深度；仅恢复原本允许写深度且已不透明的物体，防止极低透明度的页面把手机切成黑块。
- 手机材质在首次着色器编译之前固定为透明通路，避免 OPAQUE 编译标志在淡入后继续忽略 alpha；完全显示时仍恢复原本的深度规则。
- 短标注使用独立深度规则；实体页面和控件仍保留正常遮挡。本人确认标题留在手机顶部之外。
- 家人回执更新同一电脑显示面，纸条仍是唯一移动消息。任务断路位于字幕安全区上方。
- 阅读尺使用有厚度的深色边框和透明内片，与浅色排班表保持可读对比。
