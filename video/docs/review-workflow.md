# 逐镜审片

通常按分镜反馈推进；本轮保留 `narrative.md` 的叙事与文案结构，升级影棚背景、手机与指触模型，以 4K 原生采集后缩至 1080p 整片输出。
每轮直接渲染当前分镜的完整时长并编码成视频，不先渲染单帧或采样片段。
渲染完成后只报告视频路径，不自动打开审片页或播放器。
复用现有 Three.js 动画；每次渲染完整的当前分镜或连续范围。时长变化同步更新章节与字幕。
本轮输出无音轨，先确定视觉与节奏。

当前机制展开版与 214 秒整片时间轴以 `storyboard.md` 为准，不再包含旧的外卖等占位故事。

## 整片输出

```bash
cd video
npm run film -- --fps 60 --workers 1 --gpu angle-vulkan --render-scale 2
```

自动创建未占用的 `out/review/film-vNN/`，不覆盖旧版。完整渲染 12,840 帧后编码 H.264 MP4。
原始帧保留 3840×2160；最终用 Lanczos 3 缩至 1920×1080。字幕、章节导航、景深、泛光与离屏采集均匹配原生渲染尺寸；详见 `supersampling.md`。
`film.json` 记录章节、字幕与边界；`source/`、`render/`、`docs/`、`assets/` 保留制作快照。
`validation.json` 记录连续帧、逐帧异常扫描、各章交界差分和完整解码结果。
`contact-sheet.png` 仅供内部构图检查；不打开审片页或播放器。

JPEG 输入编码时显式转换为 BT.709 / limited-range `yuv420p`，避免沿用 JPEG 的 full-range 标记。
离线采集先在自有 FBO 渲染后处理、字幕和颜色输出，再用 `readRenderTargetPixels` 读取。
不读取浏览器显示 framebuffer，避免出现标签栏像素污染或孤立变色帧。

家人网页资产可用 `node render/family-assets.mjs` 重建，复用真实页面和 CSS，数据为虚构示例。
`node render/mechanism-check.mjs` 只检查整条时间轴的状态、有限数值和乱序确定性，不保存采样视频帧。
整片工程变化后不续接旧的半成品帧目录，避免混合两个源代码版本。

## 渲染

在 `video/` 中执行：

```bash
node render/review.mjs --shot prologue --fps 60 --workers 4
```

不传 `--version` 时，自动使用未占用的版本号；传入版本号时拒绝覆盖已有目录。
例如 `--version 2` 输出 `out/review/shot-01-v02/`。

中途打断后，可用 `--version 1 --resume true` 恢复未完成版本。
完整帧序列会直接进入合成，已完成的版本仍拒绝覆盖。

## 第二镜 V1：一句话开始，一句等等暂停

24 秒，承接「预约复诊」需求。单独渲染 `voice`，不重渲第一镜。

- 0–3 秒：手机与简洁入口出现，从操作手机转为开口说话。
- 3–8 秒：老人说「帮我预约一次复诊」，琥珀色光流进入手机，需求变成「预约复诊」。
- 8–14.8 秒：绿色光流随步骤播报流动，显示「正在查找预约入口」。
- 14.8–18 秒：老人插话「等等，先别办」，助手光流与波形立即停下，重新听老人说。
- 18–24 秒：接线员回应「好，先不操作」，停在「已暂停，等您决定」，不自动续办。

对话、进度与暂停画面属于动画概念示意，不是实际完成挂号的录屏。
本轮仍无音轨，使用对话文字、光流和波形呈现说话与插话。

```bash
node render/review.mjs --shot voice --version 1 --fps 60 --workers 2
```

## 第二镜 V2：顶部悬浮窗

依据实际界面参考，将办事阶段的全屏助手按钮改为手机顶部居中的绿色胶囊悬浮窗。
胶囊使用产品的绿色、浅色描边与白色文字；「正在办」文字按实际界面呼吸渐变。
状态文字沿用 `OverlayService.pillLabel`：「正在办」「正在说…」「正在听…」「停下了」。

- 0–7.8 秒：保留 App 首页的语音入口，老人交代复诊需求。
- 7.8–11.35 秒：切换至医院服务页面，助手以顶部悬浮窗伴随，不占满办事页面。
- 11.35–14.8 秒：进入科室列表，顶部播报状态与对话相呼应。
- 14.8 秒起：老人打断，医院页面立即冻结；顶部先听、再回应，最后显示「停下了」。
- 停止后只有回应声流出现，医院页面不继续操作，也不自动恢复办理。

医院页面是虚构的动画示意，不是实际医院截图或完成挂号的证据。
本版不改动第一镜，仍整段渲染 24 秒并编码，不自动打开审片页。

```bash
node render/review.mjs --shot voice --version 2 --fps 60 --workers 2
```

## 第二镜 V3：在同一镜内展示语音到工具的闭环

技术流程嵌入第二镜中段，不新增第三镜，不改动第一镜或后续章节时间。
时长仍为 24 秒，开场交代复诊需求，收尾回到顶部悬浮窗与语音暂停。

- 0–3.7 秒：老人说出需求，镜头从手机向语音数据推进。
- 3.7–7.1 秒：原始 PCM 录音经自有语音代理转发至讯飞 IAT，声波转为识别文字。
- 7.1–10.1 秒：文字先返回本机；AgentLoop 观察当前页面，将文字、页面、工具目录与历史消息送给模型。
- 10.1–12.8 秒：展示真实工具名的目录与 `open_app` 调用提议；目录不等于同时执行所有工具。
- 12.8–15.7 秒：本机检查调用，本例已取得打开新应用的同意，随后显示医院服务页面。
- 15.7–17.7 秒：工具结果以 `role: tool` 与对应 `tool_call_id` 回传，结合新页面进入下一轮。
- 17.7–18.6 秒：展示尚未执行的 `click` 提议；老人打断后取消继续操作。
- 18.6–24 秒：镜头回到老人和手机，悬浮窗先听、再回应、最后显示「停下了」，不自动续办。

过程依据 `docs/architecture.md`、`VoiceSession.kt`、`ServerClient.kt`、
`server/app/main.py`、`server/app/speech.py`、`CloudPlanner.kt` 与 `core/AgentLoop.kt`。
ASR 不直接把声音交给大模型；大模型不直接控制手机，工具由本机执行。
`医院服务`、目标控件 `e7` 和识别结果均为虚构流程示意，不是实际医院执行记录。
未声称挂号已经完成；语音服务和模型服务的动画位置也不代表同一提供方或物理部署。

```bash
node render/review.mjs --shot voice --version 3 --fps 60 --workers 2
```

## 第二镜 V4：28 秒架构展示与空间化运镜

第二镜延长至 28 秒，约 19 秒用于语音识别、模型请求、工具调用和架构闭环。
新增的 4 秒用于完整架构鸟瞰，不简单地拉慢已有视频。
后续章节、字幕、共享手机姿态与共享运镜统一顺延 4 秒；第一镜不变。

- 声波穿过有深度的传输环，进入语音识别；文字先返回本机，不直接交给大模型。
- 技术面板增加渐变、分区线、状态灯和背板，区分协议、模型与工具。
- 选中的 `open_app` 数据包从工具目录飞入本机守卫，经过确认后执行。
- 17.25–21.1 秒拉起完整架构，展示语音代理、ASR、AgentLoop、模型提供方、工具守卫和手机。
- 琥珀色表示语音前置链路，绿色表示模型请求和调用，蓝色表示工具结果与新页面观察。
- 语音前置链路保持静态；工具循环中的数据包按请求、调用、执行、再观察依次行进。
- 鸟瞰与侧向环绕用来强调空间连接；主要说明文字仍正对镜头，保证可读性。
- 22.6 秒打断后停止继续执行，26.15–28 秒保留顶部悬浮窗与暂停收尾。

架构鸟瞰是流程概念图，不表示所有接口同属一个云服务，也不表示未授权的多工具并行执行。
本机的 `CloudPlanner` 是 HTTP 客户端，模型提供方是远端服务；两者在概念图中区分。

```bash
node render/review.mjs --shot voice --version 4 --fps 60 --workers 2
```

## 第三镜 V2：修复单帧采集异常
