## 叙事修正

删去 57—66 秒提前出现陈医生与 09:00 的读表镜头。正确顺序是：当前页面与需求 → 办事步骤 → 压缩操作负担 → 留下待补医生 → 家人补充线索 → 当前目标重绑定 → 到达排班页后读表。现有 102—109 秒读表分镜保留。

## 一个连续的视觉动作

- **57—61 秒：页面拆开。** 科室页按原始像素切成五段，带着页面纹理展开成有顺序的步骤长卷，不另外插入一张排班表。
- **61—64 秒：步骤与决定分离。** 长卷呈现确认当前入口、选定科室、定位医生、读取排班、整理核对项。科室、时间来自已知需求；医生明确待补充。后续步骤是计划，不表示预先读取了未到达的页面。
- **64—69 秒：操作折叠。** 镜头绕到斜前上方，看见五段步骤通过相连的铰接点收成薄层；已知需求和医生缺口留在空中。折叠表达减少人的操作负担，不表示已经执行这些步骤。
- **69—72 秒：决定留下。** 镜头回正，普通内科、周四上午与上次那位医生三个事项成为主体。
- **72—75 秒：问题接力。** 只留下“上次，是哪位医生？”，镜头跟随缺口靠近，接回原有家人求助镜头。

## 实现与检查

独立三维五折铰接页，纹理由现有科室页生成；无外部生成图。字幕同步修改，编译隐喻明确标为过程示意。入口与出口相机按基线混合，世界矩阵与乱序渲染确定性检查覆盖折叠及交接全过程。保持技术边界：医生未获知前不指定姓名，未知页面到达后再观察，本人保留核对与提交。

动态中文纹理在本机加速 2D Canvas 上出现过字形缓存污染，最终渲染禁用该项加速，三维渲染仍走 ANGLE/EGL。未修改部分与 v12 冻结源在同光栅设置下比较，不放宽像素容差；交付帧继续硬链接 v12 原文件。步骤纹理在揭示完成后停止重复上传，仍支持乱序回看。

首轮四 worker 采集的逐帧终检发现五张仅剩字幕、三维层为空的帧，不能通过 JPEG 文件大小识别。新增编译镜头中央三维内容采样，低于阈值时在同一时刻完整重新绘制，连续三次异常即终止，避免把仅有字幕的黑场当作合格画面。最终整段 57—75 秒以两 worker 重新采集，再重新编码整片与带上下文的片段，不以五张补帧代替整段重渲染。
