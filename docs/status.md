## 交互与确认边界

**确认边界是可逆性，不是"有没有碰屏幕"。** 此前 9 个工具都标"需确认"，循环对批次里每个动作各问一次：一次 10 步任务会打扰老人约 9~12 次，而每次都要求他做技术判断——那正是他求助的事。

| 情况 | 处理 |
|---|---|
| 有文字的普通动作（点击、输入、滚动、返回、打开应用…） | **不问**，直接执行（服务端仍会内容检查）|
| 坐标点按 `tap_xy`（读不到控件时唯一无法校验的动作）| **每次任务问一次**，同意后不再重复 |
| 付款、结算、下单、发送、验证码、密码、身份、删除等 | **不问，且直接拒绝**：交回老人自己完成（`requires_user`）|
| 老人想中止 | 点开胶囊就有"停下来" |

**"要您自己做"的步骤会自己弹出来**（此前 `PAUSED` 不在自动展开集合里，老人只看到一个小胶囊，不知道要他做什么）：

- 首选路径是模型主动交回老人（`ask_person`）。实测（美团走到结算页）：*"订单已到结算页：黄焖鸡米饭1人份微辣，共25.9元，送到…。请您自己点'立即支付'完成付款。"* ——金额、地址、点哪里都说清了，没去碰按钮
- 兜底路径是模型去点危险控件被服务端拒绝（`requires_user`）→ 面板标题**「这一步要您自己做」**，正文**点名要按哪个控件**（"这一步得您自己点「去结算」。点完按下面的按钮，我接着办"），主按钮**「我做好了，继续」**
- 两条路都会自动展开面板

实测（生产确认模式，美团点外卖）：**打扰 0 次**、直接执行 9 次、危险步骤 1 次被拒并交回老人（改造前约 9~12 次打扰）。微信（盲页面、全是坐标点按）只问 1 次。

**盲页面的键盘可以按编号点按**（实测）：微信输入法（`com.tencent.wetype`）的窗口对无障碍可见，
弹起时有 12~19 个节点，以 `k` 前缀单独列出并附位置（`[k10]?@0.58,0.65`）——IME 的键大多
**没有文字**，位置是模型把截图里的候选词对上编号的唯一线索。键盘窗口只在键盘真的弹起时存在
（`dumpsys` 的 IME inset 是过期记录，不可作为判断依据）。另：盲页面 `paste_text` 找不到可编辑
焦点时不会由应用隐式点坐标；模型必须先显式用 `tap_xy` 选择输入框，再由 `paste_text` 检查焦点并尝试粘贴，失败就交还老人。

**拒付词表**：覆盖支付、下单、转账、发消息、验证码、身份认证、删除等类别，并随实测继续扩充。它只是**自动**闸门；**人工**闸门是上面的确认边界与 `ask_person`，两者互为补充。

## 悬浮窗（接线台）

- **位置**：顶部居中、**状态栏正下方**。放到状态栏那一行试过：能画出来但**收不到点击**（状态栏区域的手势归系统）
- **收起态**：小胶囊 72×38dp（实测约 234px 宽），文字居中，状态变化时文字跟着变：工作时"正在办 N"、空闲"银龄"、需要老人时"等您操作"、收起的结果"已完成"
- **展开态**：从状态栏下方垂下，最大宽度 = 屏宽-28dp（上限 420dp），结论块可滚动
- **半透明**：面板 93% 白，结论块 90% —— 不透明的大白板盖在老人正在看的应用上太压人
- **展开/收起动画（灵动岛式形变）**：**窗口尺寸逐帧变化**，顶边固定、内容被圆角壳裁切着"露出来"（`clipToOutline`），圆角从全圆渐变到卡片，**背景色同时插值**（白 ↔ 青绿）。曲线 `PathInterpolator(0.22, 1, 0.3, 1)`，展开 340ms / 收起 260ms
  - **不要用 `scaleX/scaleY` 缩放**：那看着像左右拉伸，内容还会被压扁
  - **颜色必须一起插值**：两态颜色不同，换色跳变会在收起瞬间闪出一整块面板大小的绿色
  - 窗口宽高必须走 `window.updateViewLayout` 下发，直接改 `root.layoutParams` 不生效
- **自动展开只在状态变化时发生**：每次刷新都强制展开会导致点"知道了"收起后立刻又弹开、**根本关不掉**
- **工作时自动收起**：这是正确性问题，不只是观感——展开的面板会**盖住 agent 正在截图读取的页面**。实测：上一轮的结果卡片摊开时，下一轮截图挡住了课表左半边的列，模型因此把相邻列算进目标列；改成工作时自动收起后，同一任务 **3/3 读对**
- **找家人是"生成草稿"不是"代发"**：实测误触会打开短信会话并填好求助草稿，**不会自动发送**（短信库里最新一条仍是 2021 年）

## 设计规则

- **触发推送，方法拉取**：模型不知道自己该去查技巧，所以"什么情况查哪个技巧"写在系统指令里；"具体怎么做"放在技巧里
- **但两者不能重复**：指令里把方法写全，技巧就被架空——实测同一任务，方法写在指令里时 `load_skill` 调用 **0/4**；把方法搬回技巧、指令只留"情况 → 技巧名"的对照后，`load_skill` **3/3**，任务读对率 **2/4 → 3/3**
- **观察层的缺失很容易被误读成模型能力不足**：已修的四次都属于这类——底部导航被截断、页面内容从未进入对话、滑动条被丢弃、显式截图被静默丢弃
- **推送式 vs 拉取式**：模型在"意识到自己卡住之前"就该主动做的事（例如图形页自动截图），应下沉到系统指令或观察层；等它卡住后再拉技巧，已经晚了

## 结果校验：机械层（已实现）

起因是一次现场抓到的谎报：那一轮动作只有 `open_app / wait / tap_xy / screenshot`，却收尾说
"已帮您把消息发出去了…时间是 17:37，发送成功"——它把**老人在这一轮开始前**自己发出的那条消息
算成了自己的成果。这不是感知问题，是判定问题。

`OutcomeCheck`（纯 core，可被 harness 覆盖）在循环准备以"完成"收尾前检查：

| 规则 | 内容 |
|---|---|
| **R1 文字来源** | 声明引用了"发出去的/填进去的文字" → 本轮必须真的成功执行过 `input_text`/`paste_text`/`type_text`，且文字对得上。借来的消息、预先填好的输入框都会落空 |
| **R2 时间锚点** | 声明里引用的时刻早于本轮开始 → 那是**运行前就存在**的东西，不算成果 |
| **R3 断言改变却没动手** | 声明含改变类说法，但本轮没有任何改变类动作 → 只看了屏幕 |

判定不通过时，**不以"完成"收尾**：改成如实告诉老人"我没法确认这件事真的办成了（原因）"，
把决定权交回（面板给"接着办"），并在对话里给模型一次真去做、或如实说明做不到的机会。

刻意收窄的地方：词表**只收**"对外部世界产生影响"的说法（已发送/已下单/已填/已设置…）；
泛指完成（办好了、已完成、看好了）**不算**——否则会误伤只读任务的诚实回答。这是**下限而非证明**：
它拦得住"物理上不可能"的声明，拦不住"确实动了手但没做成"。

## 技能固化（本轮原型，真机尚未验证）

已接入一条最小闭环：任务以 `COMPLETED` 收尾且通过 `OutcomeCheck` 后，结果页出现“这次办成了，
记住这个方法”；老人确认后调用一次纯文本模型请求，把本次轨迹总结成 `skill.md`，写入
`files/skills/candidate/`。家人设置里可以查看、采用（移到 `active/`）或删除候选；采用后的
技能会进入 `load_skill` 说明和当前 App 的页面提示，也可以回退到 `retired/`。全程只存文字步骤，
不存截图、坐标。

边界同样明确：候选生成不等于自进化已经闭环。当前没有失败轨迹归因、用户纠正采集、独立任务
验证、页面回放或按版本效果比较；候选内容是否准确仍依赖模型总结和家人采用，尚未在真机上走过
“生成候选 → 采用 → 下一次任务复用 → 失败回退”的完整实测。

## 已知问题

按影响排序：

| 问题 | 现象 | 影响 |
|---|---|---|
| **证据层校验仍未做** | 已有机械层（`OutcomeCheck`：文字来源、时间锚点、改变类动作，见下），它只能否掉"物理上不可能"的声明；**判断屏幕上是否真的出现了成果（比对前后截图）还没做** | 模型仍可能在"确实动了手但没做成"时误报成功。这是对老人最有害的一类错误，结论卡片会**放大**它 |
| 密集表格可能读错列 | 课表这类格子内容，模型会把相邻列的内容算进目标列。已加 `reading_tables` 技巧（先核表头、逐条按"列头+内容"念一遍自检），改进后 **3/3 读对** | 样本仍小，长期错误率待观察 |
| 坐标点按无法做内容校验 | 读不到控件时只能用坐标点按 | 护栏是"每次任务确认一次"。不做"坐标→控件"反查：会误伤（如消息列表里的"付款成功 ¥20.00"），且无障碍树不一定完整 |
| 进展检测有盲区 | 动作周期检测（周期 2/3，3 个完整周期才算，独立预算 4 次提醒）能停下"进入→退出"循环；但"在同一类动作里到处点新地方"（每步都是新页面且不成周期）与周期长于 3 步的循环仍检测不到 | 靠步数上限兜底 |
| 输入框定位反复 | 美团 8 次 `not_editable`，试 4 个编号才找到搜索框 | 浪费步骤 |
| 截图偶发失败 | 错误码 1（内部错误），同任务重跑恢复 | 盲页面任务中断 |
| 上下文随步数增长 | 10 步 4 倍，无压缩策略 | 长链路会变慢 |
| 页面文本含个人隐私 | 拼多多确认订单页把姓名、手机号、完整住址发给了模型服务 | 无脱敏、无按应用排除。已确认"既要能操作又要不外发"在云模型下无解 |
| 模型会给出付款类选项 | `ask_user` 的选项中曾出现"2份都要，直接付" | 提示词禁止付款，但选项文字未过滤 |
| 总结质量不稳定 | B站两次：一次列出 43 条明细，一次只说"主要是投稿视频" | 结果可用性波动 |
| `DecisionCache`/`RecipeCache` | 已确认从未接入循环，键含每次都变的 revision，接上也命中不了 | 已删除，避免保留一条不存在的缓存/回放路径 |

## 老人端 UI（本轮重构）

**一份措辞、一份配色，两个界面共用**：首页是 Compose，悬浮窗是 WindowManager 里的 View 代码，
两者无法共用组件，但**状态说法与颜色只有一处**（`Ui.kt` 的 `statusText(phase)` / `statusTone(phase)`
与 `Elder` token；View 侧由 `OverlayUi.kt` 提供对应的构造器：card/statusRow/button/option/bubble/shell）。
此前悬浮窗里散落着 `Color.rgb(196,106,20)`、`textSize = 19f` 这类手写值，和首页说法也不一致
（首页"停下了"、悬浮窗"已暂停"），现已全部收拢；重复的 `TaskPhase.title()` 已删除。
真机逐状态截图验证：正在办（气泡）、办事中手动展开（停下来/收起）、等您点一下确认（确认/取消）、
✓ 办好了（结果卡 + 淡色结论块）、这一步要您自己做（"我做好了，继续"）、停下了。


原则：**一屏一件事**。首页中央只有一个**大圆形按钮**——空闲时是"说给接线员听"，办事中变成
"停下来"（一个按钮同时解决"怎么说"和"怎么停"）。上方一行状态（"● 我在/正在办/等您操作/办好了/
停下了"），下方一行提示。**只有需要老人做决定时才出现卡片**（回答、等您操作、结果），
历史任务、权限、配置全部移出视线；"请家人帮忙/给家人打电话"降级成底部小字（老人的安全网）。
配置收进"家人设置"，入口是右上角很淡的齿轮 + 首页长按标题。

**同一次重构里抓到的两个平台硬事实**（这台 ColorOS 手机）：

| 事实 | 证据 | 后果 |
|---|---|---|
| **没有系统语音识别** | `pm query-activities -a android.speech.action.RECOGNIZE_SPEECH` → **0 个** | 点语音按钮会抛 `ActivityNotFoundException` **直接崩掉**。现在：探测不到 / 启动失败就永久降级为"打字告诉它"（提示可用键盘上的话筒），并保证不再崩 |
| **语音播报（TTS）已可用** | `[speak] 使用引擎：系统默认` → `开始朗读` → `朗读完成`（`onDone` 在播放结束后触发，即真的合成并播出了） | 结论：**能朗读**。设置页显示引擎状态，并可一键跳系统"文字转语音" |

**曾经的误判与真正的根因（值得记下）**：一度以为"这台手机没有语音引擎"——`tts_default_synth=null`，
而且应用侧 `getEngines()` 返回空。真正原因是 **Android 11 的包可见性**：应用不声明
`<queries><intent><action android:name="android.intent.action.TTS_SERVICE"/></intent></queries>`
就**看不到也绑不上**任何语音引擎（`adb shell pm query-services` 能查到，应用查不到）。
补上声明后默认引擎直接可用。教训：**"应用查不到" ≠ "系统没有"**，尤其是 Android 11 之后的所有
`queryIntent*`；本项目还有一处同类查询（识别）已一并声明。

**语音识别仍是"键盘里的话筒"**：这台手机没有注册 `RecognitionService`（`SpeechRecognizer.
isRecognitionAvailable` = false），也没有 `RECOGNIZE_SPEECH` 的 Activity；语音输入只存在于
百度输入法键盘内与小布助手里，不对外开放。所以首页的圆按钮在这类手机上显示"打字或说话"，
点开即聚焦输入框（键盘与话筒立刻出现），提示"点键盘上的话筒就能说话，也可以打字"。
要真正做到"应用内直接听"，只有三条路——自带离线识别（sherpa-onnx 之类，几十 MB）／
走服务端云识别（有成本、音频出设备）／依赖系统服务（这台没有）。

## 家人与社区（M1 已实现，真机验证）

老人办不了的事需要有人接手，而"有人"必须落在**任何手机都收得到的地方**：家人不用装应用，
打开一条链接就能看到情况、点"我来处理"。

服务端 `server/`（Python + FastAPI + SQLite，无 ORM）。手机端配对后：守护服务每
`heartbeat_seconds`（默认 300s）报到一次，报平安/异常/求助都上报；心跳同时也是手机的**收件箱**。

| 规矩 | 实现 |
|---|---|
| 角色决定可见范围 | `VISIBLE_KINDS`：家人全部；社区只看求助与异常；邻居只看求助。**求助里的"老人在做什么"只给家人** |
| 只有家人能给老人留话 | `/family/message` 对社区/邻居返回 403 |
| 失联只有服务端能发现 | 手机关机/没电/被杀时自己说不出话；`watch.check_silence` 对**每次中断只提醒一次**，措辞是"可能只是没电/关机" |
| 不做远程控制 | 只给状态和请求；远程协助/屏幕共享正是要防的诈骗手法 |

**真机验证的完整闭环**：老人点首页「请家人帮忙」→ 服务端收到求助（含"目标/卡在"上下文）→
家人网页看到并点「我来处理」→ 服务端排队 ack → 手机心跳取回并显示。家人手机号不再是必需的
（`hasHelpChannel()`：配对了服务器就不该再要求填号码）。

顺带修掉一个从没生效的功能：**`PeaceCheck.tick()` 之前没有任何调用者**，也就是说"每日报平安"
在真机上从来没自动跑过；现在挂在守护服务每 60 秒的循环里。

**M1 边界**：不发短信（`notify.py` 只写日志，真实短信需要服务商与模板审核）；没有账号密码
（设备令牌 + 配对码会话）；没有派单/值班（M3）；老人手机上的大字卡片与语音播报已接入：
家人留言和认领回执经心跳回来后，会以大字卡片显示并立即朗读，点“知道了”收起后回到原任务。

## 守护与保活（长跑能力）

这是"平安确认"这类看护功能的前提：**看护必须一直在看，否则"没消息"无法与"看护已死"区分**。

| 环节 | 实测 |
|---|---|
| 常驻前台服务 | ✅ 打开 App 即启动；`isForeground=true`、类型 `specialUse`、通道 `hotline_alive`。它是把进程（以及同进程的无障碍服务）钉住的手段 |
| 掉线看门狗 | 已实现：每分钟检查无障碍是否在运行，连续 3 次判定掉线后弹"接线员的能力被关掉了"通知并引导一键恢复；恢复后自动清除该通知 |
| 每日报平安 | ✅ 判定已并入 core（`DailyOk`）：有活动且到点 → 报"今天几点用过"；没活动且过宽限期 → 发提醒；一天最多一条；**没在看时绝不判定**（9 项 harness 检查覆盖） |
| 自愈钩子 | ✅ **已验**：无障碍被系统重新绑上时（`onServiceConnected`）自动拉起守护服务——比等开机广播可靠得多 |
| 开机广播 | ❌ **不可靠**：本机两次重启都没收到 `BOOT_COMPLETED`（权限已给自启动）。ColorOS 会拦截非白名单应用的开机广播 |
| 重启后的无障碍 | ❌ **会被系统移除**：两次重启后 `enabled_accessibility_services` 里都不再有我们，只剩 OPPO 自己的。这是系统的安全设计（防止恶意应用长期持有无障碍权限），不是能靠应用侧修掉的问题 |
| 通知权限 | 必须由本人授予：`pm grant` 被系统拒绝（shell 没有 `GRANT_RUNTIME_PERMISSIONS`）。未授予时前台服务照常运行，但**通知不可见**——看门狗等于哑的 |

设置页的「一直运行」把四样状态如实显示（无障碍 / 电池优化 / 自启动 / 通知权限），每一项都给出入口，并提供"重新检查"。

**由此得出的产品结论（已采用）**：*一个死掉的看护无法报告自己死了*，而这个平台不允许应用获得系统进程般的待遇。于是：

- **定位改为"在场时帮你把事办成"**，不承诺 24 小时看护
- **平安确认降级为家庭约定**：每天一条"报平安"（有活动就报"今天几点用过，一切正常"；到点还没活动就发提醒），**收不到就打电话**。沉默的含义被翻转：不是"没消息=没事"，而是"没消息=该确认一下"；手机没电/服务被杀时，缺的这条消息本身就是信号
- 一天最多一条消息（报平安或异常提醒，二者互斥），避免刷家人
- 首页在无障碍未开启时**明说"我现在看不见屏幕"**，不装作正常；设置页把四项保活状态（无障碍/电池/自启动/通知）如实显示

服务端心跳（应用每天 ping、漏了由服务端通知家人）是更可靠的下一步，但需要账号、存储与隐私设计，暂缓。

## 环境事实

**观察与输入**

- 微信、银行类应用屏蔽无障碍读取，页面控件列表为空，只能靠截图 + 比例坐标点按
- 微信不接受程序写入文字，也不接受外部注入；可行路径是"剪贴板 → 输入法候选栏"，且已加 `finally { clearPrimaryClip() }` 在粘贴完成后立即清理剪贴板隐私
- **截图坐标增强**：在 10% 主刻度网格基础上增加 5% 半透明辅助网格，坐标参考密度翻倍，辅助视觉大模型提高点按定位精度
- **坐标量化校准模式（`calibrate_coords`）**：在真机上用已知控件的真实 bounds（自动处理文字子节点与点击父节点层级），量化评测视觉模型对屏幕控件中心点的预测误差（命中率、mean/p50/p90 像素误差、系统性偏移 dx/dy）
- **喜鹊儿课表：无障碍树里只有节次数字和日期表头，一个课程名都没有**（自绘/WebView）。唯一答案来源是截图
- 12306 首页公告含"收款方"，曾使整页被误判为敏感页而**全盘禁用**。整页敏感判定已放宽为"存在可见密码框，或敏感词出现在**可操作**控件上"
- ColorOS 字体设置：字体大小是 5 档滑动条，改完需点底部"应用"。滑动条无文字、不报告 clickable，需靠 `isSlider`（识别 `SeekBar`/`AbsSeekBar`/`rangeInfo`）识别；调整用 `scroll down/up`（内部走 `ACTION_SCROLL_FORWARD/BACKWARD`），且少控件页面不会被误当成纯图页吞掉
- 美团有完整控件树，视觉未用上（截图 0 张）

**截图管线**

- 原生分辨率 + 无损 WebP。离线 A/B（同一张课表，每变体 3 次）：712×1568 JPEG80（旧）= 3 次错 1；原生分辨率或无损（PNG / WebP / JPEG 4:4:4）全部 3/3 正确
- 无损 WebP 原生分辨率只有 151KB，比旧的压缩 JPEG（154KB）还小——手机界面是大片纯色 + 重复字形
- 采集与编码已拆开：超时只管采集，编码放后台线程（此前编码在主线程上，会把辅助功能服务一起卡住）

**对话与时间**

- 老人用相对时间说话（"明天/下周"），而请求里没有任何地方说明今天是几号：已加 `current_time` 工具并在指令里要求先用它。实测日期判断正确（9月29日周二 → 明天9月30日周三）
- 显式 `screenshot` 的结果曾静默丢失（图片挂在 TOOL 消息上，而只有最后一条消息的图片会被发送）：现已搬到页面观察消息上，并保证每张图只发一次
- 查阅类动作（`current_time`/`load_skill`/`screenshot`/`wait`）不计入停滞判定——它们本来就不会改变页面

**密钥与隐私**

- 访问密钥用 Android Keystore（AES-GCM）加密后存在本机 `shared_prefs`：家人配置一次，重启/被杀/重启手机后仍可用。换机需重填；Keystore 密钥失效（改锁屏、数据恢复）时清除存储并提示重填，不猜；`SecretStore` 加密版本号与 `ServerClient` 内存 token 缓存联动失效，避免配对重置时读取脏 token
- 密钥不写进对话记录、任务存档；`files/loop.log` 只记"已设置(35位)"——此前会写前 6 位，已改掉
- 真机上"设备被 root"仍可提取，彻底方案是自建中转（密钥放服务端），但那要服务端 + 账号 + 隐私说明；中转同时也是"页面文本脱敏"的唯一介入点

**平台**

- 强制停止应用后，辅助功能服务有时不会自动重绑
- 状态栏区域收不到点击（悬浮窗不能放在那一行）
- 部分电商应用点"下单"会**直接跳转到第三方支付页**（且是读不到控件的盲页面）；未支付的订单会倒计时自动取消

## 回归校验

```bash
harness/run.sh      # 149 项 JVM 检查
cd server && pytest # 31 项服务端检查
```

JVM 上对着严格校验 transcript 的 mock 提供方跑（**149 项**）：循环、协议转换、审批策略、停滞与周期检测、观察层呈现、收尾语义、结果校验（含多引用正文与收件人解耦测试、用一个会撒谎的 mock 提供方跑完整循环）。服务端有 **28 项** pytest 覆盖鉴权隔离、心跳失联、配对码 TTL 与音频转写防护。此外，`core` 模块补充了 `AgentLoopCancellationTest`（协程取消安全性）与 `OutcomeCheckTest` 单元测试。**Android 侧（辅助功能服务、截图管线、悬浮窗、真实应用）没有自动化测试**，靠真机手工验证，结果记在上面。详见 `harness/README.md` 与 `server/README.md`。
