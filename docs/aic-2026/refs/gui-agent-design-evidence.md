# 图形界面智能体：可引用的外部证据清单

用途：为方案书中"机制为什么这样设计"的论证提供出处。
生成日期：2026-10-04。

## 使用约定（重要）

- 本清单里的数字**全部来自公开论文或官方榜单页面**，由本团队调研时抓取核对，**未由本团队复现实验**。引用时请写"文献结果"，不要写成"本作品实测"。
- 每条给出 `[出处]`（arXiv 号或 URL）与 `[取证方式]`：
  - **抓页面核实** = 调研时实际抓取了论文 HTML / 官方榜单 JSON / 项目页并读到该数字；
  - **论文自称** = 读的是摘要或作者自述。
- 每条附 `[在本作品中的用途]`，说明它支撑哪个设计决定。**没有用途的数字不要往正文里搬。**

## 一、候选清单优先于图上标注（支撑：坐标落地机制）

**同一模型、同一批任务的对照（GPT-4V，SeeAct）**

| 接地方式 | 步成功率（三组） |
|---|---|
| **给候选清单让模型选**（Textual Choices） | **39.1 / 32.7 / 42.0** |
| **在图上画框加编号**（Image Annotation，即 SoM 式） | 20.3 / 13.9 / 23.7 |
| 人工接地（上界） | 61.9 / 65.0 / 62.1 |

- `[出处]` SeeAct（arXiv:2401.01614）
- `[取证方式]` 抓页面核实
- SeeAct 正文原话：set-of-mark prompting "turns out to be **not effective** for web agents"。错误归因：**54% 的错误是模型编造了不存在的框和编号，46% 是看得见框却对不上编号**。
- 标记消融结论：**左下角数字标签（bottom-left number labels）最优**。
- `[在本作品中的用途]` 解释为什么第 1 条机制做成"点按必须落在已列举的控件上、点不到就拒绝"，而**不是**去画 Set-of-Mark；也解释为什么图上编号即便要做也只能当**辅助**，文本清单才是决策接口。

**AndroidWorld 上的同一结论（含负收益）**

| Agent | 输入 | 基座 | AndroidWorld SR |
|---|---|---|---|
| Human | — | — | 80.0 |
| M3A-Simple | a11y 树 | GPT-4 Turbo | **19.8** |
| M3A（含 guidelines + 前后状态反思） | a11y 树 | GPT-4 Turbo | **30.6** |
| M3A | a11y 树 + SoM | GPT-4 Turbo | **25.4** |
| M3A | a11y 树 + SoM | Gemini 1.5 Pro | 22.8 |
| M3A | a11y 树 | Gemini 1.5 Pro | 19.4 |

- `[出处]` AndroidWorld（arXiv:2405.14573）Table 3
- `[取证方式]` 抓页面核实
- `[在本作品中的用途]` 两件事：① SoM 对 GPT-4 Turbo **是负收益（30.6 → 25.4）**，所以"在截图上画编号框"必须当**假设去 A/B**，不能默认打开；② `M3A-Simple → M3A` 的 **+10.8** 是 **guidelines + 前后状态反思的合计量**，论文**没有单独消融 reflection**——**不许引用成"反思单独值 10.8 个点"**。

## 二、手势比精确点按鲁棒（支撑：升级阶梯的顺序）

| 动作类型 | 成功率（VeriGUI-3B / UI-TARS-7B） |
|---|---|
| click | 44.2% / 45.3% |
| **scroll** | **68–81%** |

- `[出处]` VeriGUI（arXiv:2604.05477）Table 8
- `[取证方式]` 抓页面核实
- 原文："scroll directions are more tolerant of coordinate imprecision"。
- `[在本作品中的用途]` 这是**升级阶梯把手势排在文字标签之前**的直接依据：`click → swipe/scroll → tap_text → zoom → handoff`。课表翻周这类任务本来就该走横向滑动。

## 三、重复无效动作是头号失败模式（支撑：有界阶梯 / 停滞检测）

- **"重复无效动作导致的执行超时"占全部失败的 72.3%**（1,265 次执行中）。
  - `[出处]` VeriGUI（arXiv:2604.05477）
  - `[取证方式]` 抓页面核实
  - `[在本作品中的用途]` 说明为什么"同锚点第二次无效果就拒绝"比"把步数上限从 5 调到 3"更对：**真正的问题是第 2 次就不该执行。**
- 同族数字：OS-Atlas-7B 的 Loop Rate 43.3%，UI-TARS-7B 13.4%（`[取证方式]` 抓页面核实）。

## 四、没有外部反馈的"自我反思"是有害的（支撑：核验必须由机械信号驱动）

- 原话：模型 "struggle to self-correct **without external feedback**, at times performance **even degrades**"。
  - `[出处]` arXiv:2310.01798
  - `[取证方式]` 论文自称
  - `[在本作品中的用途]` 解释为什么本作品不让模型自己判断"刚才那一步成没成"，而是用**本地像素/页面版本/关键词**这些外部事实。Reflexion 之所以有效（HumanEval 91%）是因为它有编译/测试这类外部信号。

## 五、通用云端模型的自由坐标接地有多弱（支撑：不走"换个更强的模型"这条路）

**ScreenSpot-Pro（全屏、高分辨率专业软件，最接近"内容画在图里"的场景）**

| 模型 | 分数 | 类型 |
|---|---|---|
| **GPT-4o** | **0.82%** | 通用商用 VLM |
| SeeClick (7B) | 1.14% | 专用 |
| OS-Atlas-7B | 18.91% | 专用 |
| **Claude Computer Use** | **17.10%** | 通用商用 |
| Qwen2.5-VL-7B-Instruct | 26.76% | 通用开源 |
| UI-TARS-1.5 | 61.6% | 专用 |
| MAI-UI-32B | 67.87% | 专用 |
| GroundCascade（训练无关级联） | **85.1%** | 级联 |

- `[出处]` https://gui-agent.github.io/grounding-leaderboard/results/screenspot_pro.json（Last updated 2026-09-10）
- `[取证方式]` 抓页面核实（另注：论文正文写 GPT-4o 0.9%、表格与榜单写 0.8%，引用时建议写"0.8%（榜单与论文表格；正文另作 0.9%）"）
- `[在本作品中的用途]` ① 说明"换更强的云端 VLM 救不了接地"（0.82% vs 专用 60%+）；② 所有高分方案**都依赖微调权重**，本项目不能微调，所以只能从**表示形式与搜索**上取收益。

**零训练机制在同一个冻结模型上的增益（OS-Atlas-7B）**

| 方法 | 总平均 | Δ |
|---|---|---|
| 直接接地 | 18.9 | — |
| Iterative Narrowing（3 轮中心裁剪） | 31.9 | +13.0 |
| **ReGround（首次预测处裁 1024×1024 重问）** | **40.2** | **+21.3** |
| ScreenSeekeR（GPT-4o 当 planner 递归搜索） | 48.1 | +29.2 |

- `[出处]` ScreenSpot-Pro（arXiv:2504.07981）Table 4
- `[取证方式]` 抓页面核实
- 注意：**图标类目标始终是重灾区（4.0% → 15.1%）**，即便加了 ReGround 也只有 15.1%。
- `[在本作品中的用途]` 支撑 `zoom(region)` 工具（裁剪放大重问）的设计与它在阶梯中的位置（第 4 级）。

**官方榜单上 zoom-in 的同模型对照**：8 组冻结模型，zoom-in 稳定 **+5.4 ～ +9.1 点**（`[取证方式]` 抓页面核实）。

## 六、动作效果的可核验性（支撑：本地像素核验）

**PUSV（arXiv:2604.18860）** `[取证方式]` 抓页面核实

| 信号 | 做法 | 阈值 | 实测 |
|---|---|---|---|
| L1 目标区域 | 点击坐标处 160×160 灰块 SSIM | **< 0.92** 判"变了" | 良性过渡 >0.97、攻击 0.54–0.63，留 ≥0.28 余量 |
| L2 全页 | 灰阶差 >20/255 的像素占比 | **> 0.2%** 判"变了" | 干净桌面良性 <0.05%/秒 |
| 开销 | 纯本地像素运算 | — | **< 0.1s**；180 次对抗试验 **100% 拦截、零误报** |

- `[在本作品中的用途]` 是我们 L1/L2 阈值的来源。**必须同时说明：本作品真机上拿不到"动作后帧"，所以 L1/L2 基本不生效**——阈值是文献值，**未在测试机型上校准**。

## 七、技能库的退化与验证（支撑：技能三层门禁）

| 论断 | 数字 | 出处 | 取证 |
|---|---|---|---|
| 技能库从"已知有用集"扩到 202 条，通过率 | **下降最高 21%** | arXiv:2605.24050 | 抓页面核实 |
| 退化分解：**shadowing 占 up to 68%**，且是**唯一统计显著**的效果 | 同上 | 同上 | 抓页面核实 |
| oracle-only 轨迹占比 | 88.0% → **64.4%** | 同上 | 抓页面核实 |
| 只加一个独立验证者、但**只有一条轨迹** | 仅 **+1.2 分**（多轨迹对比才有 7–9 分） | arXiv:2606.24428 | 抓页面核实 |
| 注入**仅占记忆 10%** 的错误但自洽经验 | τ²-bench RETAIL Pass@1 **82.5 → 77.2** | 同上 | 抓页面核实 |
| 自生成技能在冻结部署下不稳定 | Sonnet 4.6 / GPT-5.2-Codex 的 ARSR 比 No-Skill **低 10.0pp** | arXiv:2605.24117 | 抓页面核实 |
| 人工 curated 技能确实有用 | 87 任务：**33.9% → 50.5%**（+16.6pp）；**≤3 module 的 focused 技能优于大 bundle** | arXiv:2602.12670 | 论文自称 |
| 作者自写的 query 会高估检索效果 | hit@5 **高估最多 44 个点** | arXiv:2608.06196 | 论文自称 |

- `[在本作品中的用途]` ① **Tier1 反事实影子率存在的全部理由**：退化主因是"选错技能"而不是"上下文变长"，而它**在目标任务日志里看不见**；② **Tier2 必须做旧任务回归**：单看目标任务的通过率会漏掉别的轴上的退化；③ **不允许"一次成功就自动 active"**；④ 为什么技能要 focused 而不是大而全。

## 八、提示层 vs 架构层（支撑：为什么不用提示词替代闸门）

| 论断 | 数字 | 出处 | 取证 |
|---|---|---|---|
| 自适应攻击下，提示类防御与不设防无实质差别 | Spotlighting 在 Gemini-2.5 Pro **28% → 99%**；GPT-5 Mini 0% → 47%；Prompt Sandwiching **21% → 95%** | arXiv:2510.09023 | 抓页面核实 |
| 同文作者**主动跳过** CaMeL 类方案 | 理由："the attack is **guaranteed to fail** … control flow is **data-independent**" | 同上 | 抓页面核实 |
| 确定性控制层 + 被隔离的 LLM | AgentDojo 上 **0 次成功攻击**（原生 GPT-4o Mini **276 次**） | CaMeL, arXiv:2503.18813 | 抓页面核实 |
| 提示层对齐只是局部现象 | 加护栏后四轮升级 ASR **+约 20 点**；Claude 带护栏四轮 **44.2% > 无护栏单轮 33.7%**；**加护栏后隐蔽表述比显性更易成功** | arXiv:2607.29199 | 抓页面核实 |
| 安全对齐是浅层的 | 预填充对 GPT-4o、R2D2 及**所有 Claude** 达 **100% ASR** | arXiv:2404.02151 | 论文自称 |
| **约束粒度比约束大小更重要** | 同一 **0% ASR** 下：**分级放行保留 93.21–94.08% 能力**，二元拦/放只保留 **76.25–79.29%**；误拒率 5.47% → 1.84–4.09%；开销 ≤10ms | SkillGuard, arXiv:2608.30041 | 抓页面核实 |
| AgentDojo 自身承认的结构性下界 | **17%** 的用例"允许集 ⊇ 攻击所需集" | arXiv:2406.13352 | 论文自称 |

- `[在本作品中的用途]` 支撑方案书的核心主张：**不用提示词替代闸门**；正确动作是**抬高闸门的抽象层级**（模型提议"这个动作可不可逆"，本地闸门持有放行权），并把**二元拦/放改成分级放行**以换回能力。同时**禁止**再写"安全由架构保证"——本作品自己的边界探针仍有 5/6 漏拦。
- 注意：`SkillGuard` 未纳入本方案书参考文献表，正文如需引用请以 **内联 arXiv 号**形式出现。

## 九、澄清与弃权的决策理论（支撑：什么时候该问）

| 论断 | 内容 | 出处 |
|---|---|---|
| 最优拒绝规则 | 拒绝当且仅当 `d ≤ η ≤ 1−d`；**拒绝代价 `d` 必须事先给定** | Chow 1970；Bartlett & Wegkamp, JMLR |
| 行动/对话/不行动是三条线、两个阈值 | `eu(A│E) = p(G│E)u(A,G) + [1−p(G│E)]u(A,¬G)` | Horvitz, CHI'99 |
| 过度澄清与澄清不足都存在 | 过度澄清 **38%**（GPT-5.2）、澄清不足 **31%**（Gemini，任务失败时升到 48%）；**最常见失败模式是复合问题** | LHAW, arXiv:2602.10525 |
| 该文自陈缺口 | "we do not explicitly quantify the cost of user interaction" | 同上 |
| 弃权指标全集 | `URUP = 1 − Recall_abs`（该弃权没弃权）、**`ARSP`（误澄清）**、Coverage、AUROC/AUACC；"No single metric captures all aspects" | arXiv:2407.18418 |
| 计算机使用智能体的不确定性量化 | 跨供应商迁移平均仅 **+0.08**；"coverage degrades under calibration-test or interface mismatch" | arXiv:2606.25760 |
| 样本量（Clopper-Pearson，本团队计算） | 想以 95% 置信说"误澄清率 <10%"需 **30 次干净机会且 0 次误澄清**；n=20 → 13.9%；n=13 → 20.6%；测 ±10pp 需 n≈96 | 本团队计算 |

- `[在本作品中的用途]` ① 说明"1 个月内学不出澄清策略"是有依据的（28 条运行、可用人工真值 5 行）；② 说明为什么采用**证据等级 + 代价比阈值 + 上界**而不是分类器；③ 说明"候选必须来自屏幕真实文本"与"禁止复合问题"的来由。
