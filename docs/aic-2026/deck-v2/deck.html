08 怎么落地 · 办没办成谁说了算

办没办成，不听模型说

模型最容易犯的错不是没办成，而是没办成却说办成了。所以我们不让它自己下结论——只看这一轮它真正看过、真正动过什么。
四道检查，依次过
R0
这一轮真的调用过工具吗？
R1
这句话是页面读到的，还是自己打进去的？
R2
动作发生在结论之前吗？
R3
声称改变了的东西，真的动过吗？
最后只可能是三种结论
通过 本轮记录能支撑这个结论，才说「办好了」
无法确认 没有足够证据，就照实说，请老人自己看一眼
驳回 结论和记录矛盾，不算数，接着办
证据不够的时候，「无法确认」是一句诚实的回答，不是失败。

09 架构 · 一句话说清

可信不在模型里，在三样东西的绑定里

一个动作要可信，必须同时回答三个问题：它属于哪一版页面、谁批准了它、凭什么说它成了。把这三个回答做成运行时结构，就是本作品的架构。
P1 · 绑定面
它属于哪一版页面
动作只对被决定时看到的页面有效。
坐标动作绝不跨版本；控件动作只允许唯一身份重绑。
派发前重新看一次页面——不是计划时判断、执行时照旧。
ScreenActionGuard · dispatch
P2 · 授权面
谁批准了它
22 个工具 × 11 个属性，语义只来自一张表。
参数 → 危险词 → 敏感页 → 本人同意，逐层短路，后一层不能放行前一层拒绝的动作。
同意只对这一次、这一组参数有效。
PhoneTool · ManualActionPolicy
P3 · 证据面
凭什么说它成了
记录按来源分级：页面读到的算数，自己打进去的不算。
跨应用不互相作证；页面写「未签收」不能为「已签收」背书。
「完成」必须带一张可检查的证书。
