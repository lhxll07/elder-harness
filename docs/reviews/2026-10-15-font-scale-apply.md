# 2026-10-15 真机复跑发现：#17 字号「改 UI 档位 ≠ 系统生效」

## 现象

同一批次里 `#17 字太小了，帮我调大点` 重复 3 次，结果不一致。当天共跑 6 次（两批，每批 3 次）：

| 运行 | 系统报告 | 自动真值 | 动作里出现「应用」 |
|---|---|---|---|
| `17-1015-222703` | COMPLETED，核验 Supported | `font_scale 1.15 → 1.35` ✅ | 3 次 |
| `17-1015-223246` | COMPLETED，核验 Supported | `font_scale 1.15 → 1.35` ✅ | 3 次 |
| `17-1015-222728` | COMPLETED，核验 Supported | `font_scale 1.15 → 1.15` ❌ | **0 次** |
| `17-1015-222738` | COMPLETED，核验 Supported | `font_scale 1.15 → 1.15` ❌ | **0 次** |
| `17-1015-223308` | PAUSED（核验拦下） | `font_scale 1.15 → 1.15` ❌ | **0 次** |
| `17-1015-223318` | COMPLETED，核验 Supported | `font_scale 1.15 → 1.15` ❌ | **0 次** |

**成功与失败只取决于一件事：有没有点「应用」。6/6 全部吻合。**

两次成功运行的模型自述也印证了这一点，例如 `17-1015-223246`：

> 已经帮您把字体调大了：字体大小从"中号"改成了"大号"，**并已点"应用"生效**。

## 实测结论（在 ColorOS PLC110 / Android 16 上直接验证）

字体页有两个控件：`字体大小` 滑块（`AbsSeekBar`）和页面底部的 **`应用`** 按钮。

| 操作 | 页面档位 | `settings get system font_scale` |
|---|---|---|
| 起点 | 中号 | 1.15 |
| 向右拖滑块 | **大号**（控件值与 UI 都变了） | **1.15（不变）** |
| 点「应用」 | — | **1.35（生效）** |

**所以：拖滑块只改页面上的档位预览，必须点「应用」才写进系统值。**

代理本地核验记录的是滑块自身的平台值变化（`APPLIED｜同一滑块的平台值 2 → 3`），这是真的，
但它**不等于**系统 `font_scale` 变了。核验放行、结论 COMPLETED，而外部真值没动。

## 已排除的解释

- **不是「残留页面状态」**：回桌面 + `am force-stop com.android.settings` 清掉设置页缓存的档位后
  重跑 3 次，仍然只有第 1 次成功（第 1 次点应用、第 2/3 次不点），与第一批完全同型。
- **不是「连续测试导致」**：连续测试确实让失败更容易复现（见下），但单次干净运行里只要漏点
  「应用」，`font_scale` 同样不变——判别依据是动作序列，不是批次位置。

### 连续测试的次要影响（保留说明）

runner 在每次运行结束后把 `font_scale` 写回基线（`tasks/run.py` 的 `restore()`），而 OPPO 的
字体页会记住自己上次设的档位。两者叠加会让「UI 档位」与「系统值」在批内逐渐不一致：第 1 次
从桌面干净进入、点应用后页面自动退回，第 2、3 次则从一页状态未知的字体页继续。

这一层会影响**模型的定位难度**，但不改变判据：真值看的是系统 `font_scale` 是否变化，而
`font_scale` 只由「应用」决定。

## 影响

- 6 条中 3 条 `COMPLETED` 的结论与系统真值不符（`222728`、`222738`、`223318`）。
  按项目「办成有证据」的硬指标口径，这属于「系统说办成、实际没办成」。
- 另 1 条（`223308`）核验员以「结论缺少同单位总数依据」判 `PAUSED`，
  即机制本身能拦下这类未证实结论——**不是每次都放行**。

## 建议（未实施）

1. 在系统设置类任务的知识/提示里补一条：**改字号、亮度这类带「应用」按钮的页面，调整后必须
   确认已点「应用」，并以系统值回读为准**，不要以滑块自身档位作为成功证据。
2. `#17` 的核验判据应包含「系统 `font_scale` 是否真的变化」，而不只是控件平台值变化。
3. 重复运行之间，若必须回写基线，应同时把设置页恢复到干净入口（或换一条进入路径），
   避免 UI 档位与系统值处于不一致状态。
