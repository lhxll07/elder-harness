# 架构说明

记录日期：2026-10-10。本文描述现有实现，不把设计计划写成已实现能力。

## 模块职责与依赖

| 模块 | 职责 | 依赖与边界 |
|---|---|---|
| `core` | `AgentLoop`、工具模型、页面动作守卫、敏感操作策略、机械/证据核验、技能门禁 | Kotlin/JVM、协程、JSON；无 Android 导入 |
| `app` | UI、悬浮窗、无障碍动作、语音、模型 HTTP、会话/技能存储、亲友客户端 | 依赖 `core`；处理所有平台权限与设备生命周期 |
| `harness` | 假手机、假规划器、真实执行循环与 mock HTTP 提供方之间的协议回归 | 依赖 `core`；另编译 `app` 中平台无关的 `CloudPlanner.kt`，不编译完整 Android 模块 |
| `server` | SQLite 设备/亲友身份、心跳、事件、求助认领、留言、讯飞语音代理 | 不远程执行手机动作；目前按单进程部署设计 |
| `tasks` | ADB 真机任务执行、运行结果、人工真值、技能离线回放 | 独立于产品运行；跨语言观察语义由共同 golden 文件约束 |

`harness` 源码位于标准目录 `harness/src/main/kotlin/`。它复用 `CloudPlanner` 的真实协议实现，但直接引用 Android 模块源文件仍是结构债务，不应被宣传为完整的模块解耦。

### 核心源码职责

本次拆分参考 DSH（DeepSeek Harness）中 `core/agent/src/types.ts` 与 `core/agent-loop/src/agent.ts` 的协议/驱动边界，以及“抽象必须有当前使用者”的约束。这里只在既有 `core` 内分文件，不引入插件容器、新模块或运行时层。

| 文件 | 职责 |
|---|---|
| `AgentProtocol.kt` | 规划、工具调用、审批、消息、运行结果与回调的公共契约 |
| `AgentLoop.kt` | 重试策略与任务循环，继续持有派发、授权和取消的执行边界 |
| `Claim.kt` | 完成声明的数据模型、词义规则与解析 |
| `OutcomeCheck.kt` | 执行记录、核验结果与机械一致性检查 |
| `CompletionAudit.kt` | 串联机械/证据核验、复核接口与请求摘要 |

此次仅移动既有声明，包名、调用接口和核验顺序不变；风险策略、模型接入与会话格式不在此次重构范围内。

## 一次任务的路径

```text
语音/文字 → VoiceSession / MainActivity / OverlayService
         → SessionController
         → AgentLoop
           ├─ 观察：AndroidPhoneTools → ScreenAccessService
           ├─ 规划：CloudPlanner → 模型提供方
           ├─ 执行：参数/敏感策略 → 人工审批 → 页面守卫 → 工具 → 动作结果
           ├─ 失败：有限修复、卡死/循环停止、取消后补齐工具结果
           └─ 收尾：MechanicalFirstReviewer
                    → CompletionAudit（机械一致性 + 本轮证据）
                    → 仅本机通过后 CloudReviewer
         → 完成 / 待核对 / 交还本人 / 求助 / 暂停
```

`COMPLETED` 不直接等于外部业务已经成功：它表示当前核验链接受本轮完成声明。页面文字、截图、动作结果和真实业务回执的证据强度不同，演示必须区分。

会话通过同目录临时文件、同步写入和替换保存到设备私有目录，失败会提示，不把失败保存当成成功；图片不进入保存的消息。`SessionStore`、`SkillStore` 在现有 `core` 中复用，无新增仓储框架或模块。

动作后的 `ActionObservation` 只核对同一应用内可观察的事实：唯一稳定输入框的值、同一滑块的方向变化、全部明确声明且至少一个新增的文字事实。没有足够信号就返回 `UNKNOWN`；可绑定的目标值未变，或明确事实早已存在且页面未变，才判 `NO_EFFECT`；与明确预期不符为 `CHANGED_OTHER`。后两者不能被模型复核翻成办成。控件树不变不能单独否定图形内容变化；没有接通可靠前后帧的像素/SSIM链路已删除，不用动画变化充当结果。

技能先进入候选，导入独立验证报告后才能手动采用。报告绑定内容哈希及覆盖适用条件的 SHA-256 契约哈希，重算影子回放和准入条件；未标真值、自动确认、训练运行泄漏、缺少旧任务回归都拒绝。`requires` 匹配去掉提示与装饰的实际页面，提示与 `load_skill` 共用应用/任务族/前提检查。开发版的候选试用明确标注实验并强制关闭自动确认，不进入正式启用记录。见 [技能验证流程](skill-validation.md)。

## 亲友协作路径

```text
手机配对 → 设备令牌 + 有效期内且绑定角色的邀请码
亲友加入 → 服务端角色校验 → 会话 Cookie
手机事件/心跳 → SQLite → 家人网页查看与认领
亲友留言/认领回执 → 手机心跳取回 → 显示确认 → 已读确认
手机失联 → 服务端 watcher 产生事件 → 通知适配器
```

通知适配器 `notify.py` 可选接入带凭证的 HTTPS Webhook，只报告转发服务是否接收，不推断短信送达或已读。未配置、无接收成员、转发失败时，求助仍保留在网页，手机明确告知并提供电话/本人发送短信的路径。平安确认和心跳不代表医学意义上的健康状态。

### 家人端与设置分层

- `app/.../settings/SettingsScreen.kt` 管理设置总览、子页和返回；联系人、常驻权限、模型隐私、技巧审核和高级调试分区，老人首页不承担装机配置。
- `FamilySettings.kt` 复用会话的 `ServerClient`；备用电话联系人单独保存。已有配对使用 `/invite` 更新角色邀请码、`/profile` 更新称呼，不新建设备。切换服务需要确认，拿到有效响应后才替换连接配置。
- `DeviceSettings.kt` 在从系统设置返回后重新检查权限；打开自启动设置不等于已获授权。`ModelSettings.kt` 保留独立草稿，不把密钥放入可保存的页面状态；服务地址校验复用 `core/ServiceAddress`。
- `DeveloperSettings.kt` 分开控制详细日志与演示自动确认；正式构建只能关闭遗留开关，不能在界面中开启。`SkillSettings.kt` 保持现有技巧门禁，操作按钮自动换行。
- `server/app/family.py` 管理家人路由和会话退出，`family_view.py` 集中角色与隐私过滤，`web.py` 只渲染 HTML，`static/family.css` 提供响应式样式。网页与摘要 API 共用权限规则，社区/邻居不获得私密背景或成员电话号码。
- 待接手与已接手求助独立查询，不被最近记录数量截断。留言区分提交、到手机、老人已读；退出删除当前服务端会话，家人页面和摘要禁止缓存。

## 信任边界

- 用户授权决定目标和可执行范围；第三方页面、外来文本和候选技能不能获得更高的执行权限。
- 敏感工具的拒绝规则先于模型决策与人工自动确认；坐标动作仍受页面可见性和策略完备性限制。
- 系统设置不再按显示/字体白名单一律阻断：普通导航、滑块与应用调节可继续；明确危险目标及账号/权限/安全页面的模糊开关仍交还本人。页面有变化但未看到全部预期文字属于未知，不等同操作失败，更不等同完成。可读字号控件不为字体预览图额外索取截图；待确认时提供通知和语音入口，从本应用同意后先返回原页面再执行。
- 完成声明必须先通过本地核验，模型复核不能推翻本地拒绝；执行者输入的文字不能充当独立完成证据。
- 设备端使用可轮换 Bearer token，亲友端 Cookie 在服务端检查期限；成员可撤销，邀请角色与既有手机号角色不一致时拒绝复用身份。
- 模型请求可含页面文本和截图，语音代理会把录音发送给语音提供方；这不是纯端侧、零数据出网方案。排除应用和敏感页不暴露页面，已知号码/凭证格式局部脱敏；人名、病情与截图无法靠该规则全面脱敏。默认不再自动落盘调试截图。
- Android 只对 loopback 放行明文 HTTP；其他服务地址应走 HTTPS。实际部署仍需证书、入口限制、凭证轮换与日志脱敏。

## 下一阶段拆分顺序

已优先处理身份期限/撤销、会话落盘、日志、技能启用和动作核验。不为了“目录好看”引入新运行时或继续拆没有独立边界的小模块；后续拆分仅在明确阻碍维护时进行。

1. 仓储已移入纯 `core`；下一步优先在真实设备检查恢复/取消/完成，而不是继续增加仓储抽象。
2. 把平台无关的模型 HTTP 适配从 `app` 提到独立 JVM 适配模块，消除 `harness` 直接引用 `app` 源文件。
3. `MainActivity` 的设置、技巧、亲友面板已拆到 `settings/`；后续再让无障碍服务内部按观察与动作分层。
4. 拆 `AgentLoop` 的上下文预算、动作台账与收尾核验时，保持既有协议、golden 和失败路径测试不变。
