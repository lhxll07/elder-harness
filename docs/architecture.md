# 架构说明

记录日期：2026-10-09。本文描述现有实现，不把设计计划写成已实现能力。

## 模块职责与依赖

| 模块 | 职责 | 依赖与边界 |
|---|---|---|
| `core` | `AgentLoop`、工具模型、页面动作守卫、敏感操作策略、机械/证据核验、技能门禁 | Kotlin/JVM、协程、JSON；无 Android 导入 |
| `app` | UI、悬浮窗、无障碍动作、语音、模型 HTTP、会话/技能存储、亲友客户端 | 依赖 `core`；处理所有平台权限与设备生命周期 |
| `harness` | 假手机、假规划器、真实执行循环与 mock HTTP 提供方之间的协议回归 | 依赖 `core`；另编译 `app` 中平台无关的 `CloudPlanner.kt`，不编译完整 Android 模块 |
| `server` | SQLite 设备/亲友身份、心跳、事件、求助认领、留言、讯飞语音代理 | 不远程执行手机动作；目前按单进程部署设计 |
| `tasks` | ADB 真机任务执行、运行结果、人工真值、技能离线回放 | 独立于产品运行；跨语言观察语义由共同 golden 文件约束 |

`harness` 源码位于标准目录 `harness/src/main/kotlin/`。它复用 `CloudPlanner` 的真实协议实现，但直接引用 Android 模块源文件仍是结构债务，不应被宣传为完整的模块解耦。

## 一次任务的路径

```text
语音/文字 → VoiceSession / MainActivity / OverlayService
         → SessionController
         → AgentLoop
           ├─ 观察：AndroidPhoneTools → ScreenAccessService
           ├─ 规划：CloudPlanner → 模型提供方
           ├─ 执行：参数/敏感策略 → 人工审批 → 页面守卫 → 工具 → 动作结果
           ├─ 失败：有限修复、卡死/循环停止、取消后补齐工具结果
           └─ 收尾：MechanicalFirstReviewer
                    → CompletionAudit（机械一致性 + 本轮证据）
                    → 仅本机通过后 CloudReviewer
         → 完成 / 待核对 / 交还本人 / 求助 / 暂停
```

`COMPLETED` 不直接等于外部业务已经成功：它表示当前核验链接受本轮完成声明。页面文字、截图、动作结果和真实业务回执的证据强度不同，演示必须区分。

会话保存到设备私有目录用于续办；图片不进入保存的消息。技能从已确认的任务生成候选，审核后启用，`requires` 的匹配对象是去掉提示与装饰文字的实际页面观察。

## 亲友协作路径

```text
手机配对 → 设备令牌 + 有效期内且绑定角色的邀请码
亲友加入 → 服务端角色校验 → 会话 Cookie
手机事件/心跳 → SQLite → 家人网页查看与认领
亲友留言/认领回执 → 手机心跳取回 → 显示确认 → 已读确认
手机失联 → 服务端 watcher 产生事件 → 通知适配器
```

通知适配器 `notify.py` 当前只记日志；手机上的本地短信/电话能力是另一条路径，不等于服务端已经接入短信供应商。平安确认和心跳也不代表医学意义上的健康状态。

## 信任边界

- 用户授权决定目标和可执行范围；第三方页面、外来文本和候选技能不能获得更高的执行权限。
- 敏感工具的拒绝规则先于模型决策与人工自动确认；坐标动作仍受页面可见性和策略完备性限制。
- 完成声明必须先通过本地核验，模型复核不能推翻本地拒绝；执行者输入的文字不能充当独立完成证据。
- 设备端使用 Bearer token，亲友端使用 Cookie；邀请角色与既有手机号角色不一致时拒绝复用身份。
- 模型请求可含页面文本和截图，语音代理会把录音发送给语音提供方；这不是纯端侧、零数据出网方案。
- Android 只对 loopback 放行明文 HTTP；其他服务地址应走 HTTPS。实际部署仍需证书、入口限制、凭证轮换与日志脱敏。

## 下一阶段拆分顺序

优先解决审查中的身份生命周期、配对幂等、会话原子落盘和敏感日志，再拆大文件。不为了“目录好看”引入新运行时或拆出没有独立边界的小模块。

1. 从 `SessionController` 提取会话仓储接口和任务状态协调器，让恢复/取消/完成可以在 JVM 上测试。
2. 把平台无关的模型 HTTP 适配从 `app` 提到独立 JVM 适配模块，消除 `harness` 直接引用 `app` 源文件。
3. 把 `MainActivity` 的设置、技能、亲友面板拆为独立 Compose 文件；无障碍服务内部按观察与动作分层。
4. 拆 `AgentLoop` 的上下文预算、动作台账与收尾核验时，保持既有协议、golden 和失败路径测试不变。
